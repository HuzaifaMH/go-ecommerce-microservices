# inventory-service

Owns stock levels and reservations. It reserves stock for an order all-or-nothing, releases it when the saga rolls back, and tells the order-service what happened.

## Interfaces

| Kind | Name | Description |
|---|---|---|
| gRPC | `InventoryService.GetStock` | One item by SKU (`NOT_FOUND` if unknown) |
| gRPC | `InventoryService.ListStock` | Paginated list ordered by SKU (opaque page token) |
| Command | `inventory.cmd.reserve` (`ReserveStock`) | Reserve every line for an order, or none |
| Command | `inventory.cmd.release` (`ReleaseStock`) | Give a reservation back (saga compensation) |
| Event | `inventory.evt.reserved` (`StockReserved`) | Reservation succeeded |
| Event | `inventory.evt.rejected` (`StockRejected`) | Not enough stock; lists the unavailable SKUs |
| Event | `inventory.evt.released` (`StockReleased`) | Reservation released (also sent if there was nothing to release) |

Contracts: [`api/proto/ecommerce/inventory/v1`](../../api/proto/ecommerce/inventory/v1). Subjects: [`pkg/subjects`](../../pkg/subjects/subjects.go).

## Behaviour worth knowing

- **All or nothing.** If any line is short or unknown, nothing is reserved and `StockRejected` lists every problem SKU.
- **Idempotent per order.** One reservation per order ID. Repeating `ReserveStock` re-publishes the original outcome and never reserves twice. Releasing twice, or releasing an order that never reserved, only re-publishes `StockReleased`.
- **No oversell under concurrency.** Item rows are locked with `SELECT ... FOR UPDATE` in SKU order (no deadlocks), and the table has `CHECK (reserved <= on_hand)` as a last line of defence.
- **Exactly-once effect.** Each command is processed through the inbox, and its reply is written to the outbox in the same database transaction, so a crash can neither lose a reply nor apply a command twice.
- **Poison messages.** Malformed commands are terminated instead of retried forever; transient errors are retried.
- **Rejection is not an error.** Running out of stock is a normal business outcome reported with an event.

## Layout

```
cmd/inventory/                    wiring only
internal/domain/                  Item, Reservation, all-or-nothing rules
internal/app/                     Reserve / Release / GetItem / ListItems + ports (Repository, Transactor, Events)
internal/adapters/grpc/           gRPC server, error mapping, pagination tokens
internal/adapters/nats/           command handlers (inbox) and event publisher (outbox)
internal/adapters/postgres/       repository, migrations runner, demo seed; sqlcgen/ is generated by sqlc
internal/integration/             end-to-end tests (Postgres + NATS)
migrations/                       goose SQL migrations (embedded in the binary)
```

## Configuration (environment)

| Variable | Default | Description |
|---|---|---|
| `DATABASE_URL` | *required* | PostgreSQL connection string |
| `NATS_URL` | `nats://localhost:4222` | NATS server |
| `GRPC_ADDR` | `:9090` | gRPC listen address |
| `HTTP_ADDR` | `:8080` | `/healthz` and `/readyz` |
| `SEED_DEMO_DATA` | `false` | Insert sample products on startup (never overwrites rows) |
| `SHUTDOWN_TIMEOUT` | `15s` | Graceful shutdown limit |
| `OTEL_EXPORTER_OTLP_ENDPOINT` | | OTLP/gRPC endpoint for traces (e.g. `http://jaeger:4317`); unset disables export. `/metrics` is served on `HTTP_ADDR` |
| `LOG_LEVEL` / `LOG_FORMAT` | `info` / `json` | `debug\|info\|warn\|error`, `json\|text` |

## Run it

```bash
make up                      # NATS, Postgres and this service (with demo stock)
grpcurl -plaintext localhost:9090 list
grpcurl -plaintext -d '{"sku":"BOOK-GO-001"}' localhost:9090 ecommerce.inventory.v1.InventoryService/GetStock
curl localhost:8081/readyz
```

## Test it

```bash
go test -short ./services/inventory/...   # unit tests, no Docker
go test ./services/inventory/...          # plus integration tests (Docker required)
```
